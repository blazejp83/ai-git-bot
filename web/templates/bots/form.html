The bot is recognised as the account its Git integration's token belongs to. This username is only used if that account cannot be read, and as an extra @mention alias.
Comma-separated target (base) branches whose pull requests are reviewed automatically when opened or updated; * and ? work as wildcards. Leave empty to review every pull request. An explicit @bot #review comment always works.
The writer asks clarifying questions or creates an "AI Created Issue" with requirements and acceptance criteria. Run it as its own bot with its own Git account and webhook: one account cannot tell "assigned to write" from "assigned to code".
The reviewer records findings with a severity (BLOCKER, MEDIUM, LOW) and exact lines; the bot posts them in a fixed layout and approves or requests changes based on the limits below. Off: a free-text review comment.
Reviewers can rate findings in a PR comment, e.g. @bot feedback R12-F2 incorrect the loop is inclusive on purpose (also retract FB3, show FB3, list). Corrective verdicts are given to later reviews of the same repository.
More findings than a limit → request changes; within all limits → approve. Leave all three blank to only comment. An inconclusive review always only comments. If the provider refuses a formal review (e.g. the bot approving its own PR), the review is posted as a comment.

Shell Allowlist (commands the agent can run)
Comma-separated list of commands the agent is allowed to run (e.g. git allows git log, git diff). Every command in a chain (&&, ;, |) must be allowed; cd, pwd, echo, printf, true, false and test always are, and $(...) is refused. This guards against mistakes, not a determined attacker: an allowed command such as find -exec or make can still run others.
